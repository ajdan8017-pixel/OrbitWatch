## 1. Использованные инструменты и методы отладки

- **Среда выполнения и инспекции:** Google Chrome DevTools (v128+).
- **Инструменты контроля кода:** TypeScript Compiler (`tsc --noEmit`), Vite HMR Dev Server, ESLint.
- **Точки останова (Breakpoints):**
  - Обычные точки останова в `Sources` (отладка расчёта матриц ECI в `SpaceScene.tsx`).
  - Условные точки останова (Conditional Breakpoints: остановка цикла SGP4 только при `sat.id === '25544'`).
  - XHR/Fetch Breakpoints (перехват сетевых запросов к `celestrak.org`).
- **Пошаговое выполнение:** Step Over (F10), Step Into (F11), Step Out (Shift+F11).
- **Инспекция состояния (Scope & Watch):**
  - Мониторинг переменных: `simulatedTime`, `selectedPos`, `celestial.sunDirection`, `trajectory.length`.
  - Мониторинг стека вызовов (`Call Stack`) при вызове `requestAnimationFrame`.
- **Логирование и телеметрия:**
  - `console.log()`, `console.warn()`, `console.error()`.
  - Табличный вывод спутниковой выборки через `console.table()`.
  - Замер времени выполнения через `console.time()` и `console.timeEnd()`.

## 2. Условная компиляция и режим отладки (Debug Mode)

В проект внедрен механизм условного логирования:
```typescript
// src/utils/debug.ts
export const DEBUG_CONFIG = {
  enabled: import.meta.env.DEV, // Автоматически true в режиме разработки
  logSGP4: false,               // Логирование шагов орбитального пророгатора
  logNetwork: true,             // Логирование статусов CelesTrak и SpaceX API
  logRenderMetrics: true        // Замер времени кадра и количества полигонов/спрайтов
};

export const debugLog = (module: string, message: string, data?: unknown) => {
  if (DEBUG_CONFIG.enabled) {
    console.log(`%c[DEBUG::${module}]%c ${message}`, 'color: #06b6d4; font-weight: bold;', 'color: inherit;', data ?? '');
  }
};
```

## 3. Журнал найденных и устраненных ошибок

### Ошибка 1: Ошибка статической типизации TypeScript (TS2339) в цикле рендеринга
- **Тип:** Синтаксическая / Строгая типизация во время компиляции.
- **Где:** `src/components/Globe/SpaceScene.tsx`, строки 602, 610.
- **Симптом:** Сборщик `tsc --noEmit` завершался с ошибкой: `error TS2339: Property 'x' does not exist on type 'never'`. Сборка прерывалась.
- **Причина:** Переменная `selectedPos` была объявлена как `let selectedPos: CurrentPosition | null = null;` и модифицировалась внутри анонимного замыкания `satSpritesMap.current.forEach(...)`. Анализатор потока типов компилятора TypeScript сужал тип переменной после цикла до `never`, предполагая, что ветка присваивания может не выполниться.
- **Решение:** Вынесено прямое вычисление координат выбранного спутника перед циклом обхода с явной аннотацией типа:
  ```typescript
  const selectedPos: CurrentPosition | null = selectedSat
    ? calculateSatellitePosition(selectedSat, time)
    : null;
  ```
- **Статус:** ✅ Исправлено.
- **Коммит:** `fix(scene): устранена ошибка вывода типов selectedPos в SpaceScene.tsx (TS2339)`

---

### Ошибка 2: Рассинхронизация вращения Земли и спутниковых орбит (географический сдвиг)
- **Тип:** Логическая ошибка математической модели.
- **Где:** `src/components/Globe/SpaceScene.tsx`, метод обновления кадра.
- **Симптом:** При длительной симуляции подспутниковая точка аппарата смещалась относительно реальных материков на текстуре Земли (МКС визуально пролетала не над теми географическими координатами, которые выводились в карточке).
- **Причина:** Группа Земли `earthGroup` вращалась с произвольной усредненной угловой скоростью, не синхронизированной с астрономическим гринвичским звездным временем (Greenwich Mean Sidereal Time — GMST), в то время как координаты SGP4 рассчитывались в абсолютной геоцентрической инерциальной системе ECI (J2000).
- **Решение:** Внедрен расчет точного угла GMST через математический модуль `satellite.gstime(timeState.simulatedTime)` с прямой установкой угла рыскания сферы Земли `earthGroup.rotation.y = gmst` на каждом кадре.
- **Статус:** ✅ Исправлено.
- **Коммит:** `fix(orbit): исправлена синхронизация вращения Земли с GMST для точного геопозиционирования`

---

### Ошибка 3: Сбой работы Web Workers при сборке в ES-модули
- **Тип:** Ошибка времени выполнения (Runtime Error) / Конфигурация сборщика.
- **Где:** `vite.config.ts`, секция сборщика.
- **Симптом:** В браузере консоль выдавала ошибку: `Uncaught TypeError: Cannot use 'import.meta' outside a module` при попытке выноса тяжелых вычислений SGP4 в фоновый воркер.
- **Причина:** Vite по умолчанию собирал скрипты веб-воркеров в устаревший формат IIFE (Immediately Invoked Function Expression), который конфликтовал с ES-модулями `satellite.js` и Three.js.
- **Решение:** В `vite.config.ts` настроена директива:
  ```typescript
  worker: {
    format: 'es',
    plugins: () => []
  }
  ```
- **Статус:** ✅ Исправлено.
- **Коммит:** `fix(build): настроена сборка Web Workers в формате ES Modules в vite.config.ts`

### Ошибка 4: Нестабильное срабатывание Raycaster при клике по микро-объектам
- **Тип:** Ошибка интеграции / Пользовательский интерфейс.
- **Где:** `src/components/Globe/SpaceScene.tsx`, обработчик `handlePointerDown`.
- **Симптом:** При попытке выбрать спутник мышью в 3D-пространстве клик регистрировался только в 1 случае из 5, выбор аппарата был затруднен.
- **Причина:** Изначально спутники визуализировались маленькими полигональными сферами радиусом 0.12 units. Стандартный луч `THREE.Raycaster` требовал прецизионного пересечения с миниатюрной геометрией на расстоянии до 40 units от камеры.
- **Решение:** Заменены полигональные меши на `THREE.Sprite` с текстурами CanvasTexture и настроен порог чувствительности луча пересечения: `raycaster.current.params.Points = { threshold: 0.8 }`, а также увеличен хитбокс при наведении курсора.
- **Статус:** ✅ Исправлено.
- **Коммит:** `fix(interaction): оптимизирован Raycasting для спрайтов спутников, исправлен захват клика`

### Ошибка 5: Блокировка интерфейса и крах приложения при отказе API CelesTrak
- **Тип:** Ошибка интеграции внешних сервисов / Обработка исключений.
- **Где:** `src/services/tleService.ts`, функция `loadInitialSatelliteCatalog`.
- **Симптом:** При сетевой недоступности CelesTrak (ошибка CORS, тайм-аут или оффлайн-режим) промис падал с необработанным исключением, приложение зависало на бесконечном лоадере.
- **Причина:** Отсутствовала многоуровневая обработка исключений (fail-safe fallback) и связь с хранилищем `LocalStorage`.
- **Решение:** Разработан каскадный механизм загрузки:
  1. Попытка запроса свежих TLE с `celestrak.org` (HTTPS).
  2. В случае ошибки — чтение ранее сохраненных валидных TLE из `localStorage.getItem('orbitwatch_tle_cache')`.
  3. В случае отсутствия кэша — мгновенное переключение на встроенную эталонную базу (`FALLBACK_TLE_DATA`) с генерацией предупреждающего тоста в UI.
- **Статус:** ✅ Исправлено.
- **Коммит:** `fix(api): добавлен многоуровневый fallback и оффлайн-кэширование TLE в LocalStorage`
