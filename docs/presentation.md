## Слайд 2. Проблема и актуальность

### Проблема
1. **Сложность восприятия орбитальной механики:** Двумерные проекции (карты Меркатора) искажают реальные наклонения орбит, апогеи, перигеи и пространственное взаимное положение космических аппаратов.
2. **Экспоненциальный рост числа спутников:** На околоземных орбитах уже функционируют тысячи спутников (Starlink, OneWeb, ГЛОНАСС, GPS), что требует наглядных средств пространственного мониторинга.
3. **Громоздкость существующих решений:** Профессиональные САПР (STK, GMAT) требуют дорогостоящих лицензий и мощных рабочих станций, а простые веб-трекеры часто перегружены рекламой или имеют низкую частоту обновления.

### Актуальность проекта
* Веб-приложение **OrbitWatch** предоставляет мгновенный доступ к прецизионным 3D-расчётам прямо в браузере без установки тяжёлого ПО.
* Решает задачу наглядного обучения студентов аэрокосмических и IT-специальностей, а также мониторинга действующих миссий.

## Слайд 3. Цель и задачи проекта

### Главная цель
Разработать и внедрить полнофункциональное, отказоустойчивое веб-приложение для высокоточной 3D-визуализации околоземного космического пространства и отслеживания траекторий спутников в реальном времени на базе математической модели SGP4.

### Задачи проекта
1. **Реализовать баллистический модуль:** Интегрировать модель SGP4/SDP4 для расчёта пространственных координат космических аппаратов по строкам TLE в любой момент времени.
2. **Спроектировать интерактивную 3D-сцену:** Построить модель Земли с кинематографическим шейдерным освещением, сменой дня и ночи, солнечной траекторией и отрисовкой орбитальных эллипсов.
3. **Обеспечить надёжную синхронизацию данных:** Наладить приём свежих TLE-каталогов из CelesTrak с многоуровневым кэшированием в LocalStorage и отказоустойчивым оффлайн-режимом.
4. **Покрыть кодовую базу автотестами и CI:** Создать набор юнит-тестов (Vitest) и настроить GitHub Actions для непрерывной интеграции.
5. **Подготовить полный комплект документации:** Разработать User Guide, Install Guide, отчёты об инспекции кода, метриках качества и дневники практики.

## Слайд 8. Баллистическое ядро и модель SGP4

### Математический конвейер расчёта
1. **Входные данные:** Двухстрочный набор элементов TLE (Two-Line Element Set), содержащий эпоху, наклонение, среднее движение, эксцентриситет, аргумент перигея и BSTAR-коэффициент торможения.
2. **Алгоритм SGP4/SDP4:**
   $$\vec{r}_{TEME}, \vec{v}_{TEME} = \text{SGP4}(TLE, t)$$
   Вычисление положения и скорости аппарата в истинной экваториальной системе координат на эпоху наблюдения (TEME).
3. **Преобразование координат в Greenwich ECEF:**
   Учёт угла поворота Земли (Greenwich Hour Angle / GMST) для расчёта географической широты $\phi$, долготы $\lambda$ и высоты $h$.
4. **Проекция в сцену Three.js:**
   Масштабирование геоцентрических координат в единицы трёхмерного мира с радиусом Земли $R = 10.0$ единиц:
   $$X = (R + h \cdot s) \cos(\phi) \sin(\lambda), \quad Y = (R + h \cdot s) \sin(\phi), \quad Z = (R + h \cdot s) \cos(\phi) \cos(\lambda)$$

## Слайд 12. Ключевые инженерные вызовы и решения

| Проблема | Техническое решение в OrbitWatch |
|---|---|
| **Высокая нагрузка при отрисовке сотен орбит** | Использование буферизованных геометрий (`LineLoop` / `BufferGeometry`) и предварительный расчёт точек траектории без пересоздания объектов сцены. |
| **Нестабильность внешнего API CelesTrak** | Трёхуровневая архитектура: Express Backend Proxy $\rightarrow$ LocalStorage кэш $\rightarrow$ встроенный оффлайн-датасет ключевых спутников. |
| **Переполнение квоты браузерного хранилища** | Обработка `DOMException (QuotaExceededError)` с автоматической очисткой устаревших кэшей и сжатием TLE-каталога. |
| **Сложность ориентации терминатора Земли** | Разработка математического модуля `astronomy.ts` для вычисления эклиптических координат Солнца по дате/времени UTC. |
